# 项目文案写作规范 —— AI 执行手册

> 本文档指导 AI 为本仓库（guizang-ppt-skill 网页 HTML PPT）撰写页面文案。
> 全部规则从 `ppt-collection/` 38 份已认可成品、602 页文案中提炼（原始数据见 `docs/copy-analysis/copy_dump.json`），是"被用户认可过的文案长什么样"的可执行描述。
> 文档分工：**AGENTS.md** 管制作流程、deck 级节奏硬规则、浏览器验收门槛与经验沉淀（本文档不重复这些）；**根目录 `ppt-copywriting-prompt.md`** 管通用叙事质量（先理解再写、避免 AI 味）；**本文档**负责本项目专属的定位、质感、结构、句式、字段和门槛。两者同时生效，冲突时以本文档为准。本文档只管文案：不定义视觉、排版、动效、浏览器验收等规则；输出中的节奏/布局标注只是给制作 agent 的交接信息。
> 度量口径：本文所有长度约束（标题每行 ≤8 字、lead 30–60 字、说明 ≤14 字）都按**渲染行/渲染后字符**计，`<br>` 切开的每一行单独计数；与根目录 prompt 的"标题 4–14 字"不冲突——那是整条标题的常用区间，本文按行收紧。

## 一、目标定位：给普通人的数据科普

一句话定位：**给普通人的数据科普**——用纪录片旁白的克制和 Apple 发布会语言的简洁，把一个专业机制讲成普通人当天就能验证的事。

内容上有三条腿，缺一条就不合格；语言上有一条质感线，贯穿每一句：

1. **科普性**：默认观众零背景。所有内容从日常生活切入，所有术语首次出现必须解释，讲机制而不是堆术语。
2. **客观事实**：文案只陈述可查证的事实、机制和数据，不渲染情绪、不编造矛盾、不为戏剧性夸大。观点必须落在来源上。
3. **数据引用**：关键论断一律用权威机构的具体数字支撑，数字带说明、带边界、带来源。没有数据支撑的论断降级为定性描述或不写。
4. **优雅克制**：像 Apple 发布会字幕一样简洁——短句、主动语态、零冗余形容词。力量来自信息本身，不来自修辞堆叠（详见第七节）。

三条腿 + 一条质感线的成品样本：冷链 deck 用「低温，让世界第一次学会保存新鲜。」一句定调（优雅克制），从观众每天都经历的牛奶、海鲜、疫苗切入（科普性），整页只陈述"低温是工程手段，不是自然状态"（客观），用 `526M Tonnes`、`13.2%` 等带来源的数据立论（数据引用）。

量化基准（写作时的硬约束，不是建议；"实测"一列来自 38 份已认可成品的全库统计）：

| 指标 | 硬约束 | 成品实测 |
|---|---|---|
| 标题 | 每行 ≤8 中文字，手动 `<br>` 断行，最多 2 行；3 行 = 重写标题 | 中文标题**每行中位数 7**、P90 13；**约 1/3 的行超 8 字**——超了就要人工核查是否可缩，而不是照搬 |
| lead | 单句 30–60 字；>70 字必须拆 | 中位数约 37，**约 60%** 落在 30–60；超 70 的仅约 4.5%，且多为复杂因果句 |
| 单句长度 | 一句一个意思，用句号切开；长从句拆成两短句 | Apple 式节奏 |
| 每页关键数据 | 1–3 个，多了拆页 | 全库惯例 |
| 疑问句标题 | 只允许用在钩子页和悬念页，全 deck ≤2 处 | 实测约 2%，悬念靠反差陈述而非问号 |
| 数字卡说明 | ≤14 字 | 全库惯例 |
| 纠偏句式标题（不是/其实/≠） | 主力句式之一，约占 9% | 实测约 8%，客观纠偏是本项目的标志性动作 |
| hero 封面标题 | 每行 ≤5 中文字（比正文页更短） | 对应 AGENTS.md `h-hero`（10vw 字号）上限 |

两个容易漏的硬约束（写作时就生效）：

- **长度超限即不合格**：lead 超过 70 字必须拆句或删减、数字卡说明超过 14 字必须压缩、标题超过 2 行必须重写——上限来自成品实测（见上表），不是建议。
- **大数字用缩写书写**：超过 4 位的数字写成 `1.6 B`、`526M Tonnes` 而非一长串 0；这是全库统一的数字书写惯例。

## 二、写作工作流（第 0 步 + 六步，顺序执行）

### 第 0 步：确认输入与输出契约

动笔前先明确两件事：

1. **收到什么**：主题 / 文章 / 研究资料 / 数据 / 用户硬约束（页数、受众、时长）。只有主题时，先确定认知缺口方向（做法见第 1 步），不要直接开写。
2. **先交付什么**：固定顺序——**认知缺口一句话 + 数据底稿摘要 + 分幕表**（见 §十一 Deck 级三件）→ 用户确认后 → 逐页文案。不得跳过确认直接产出全部页面。

### 第 1 步：找认知缺口

在写任何一页之前，先回答：**这个主题里，大多数人深信但不准确的那个"X"是什么？**

成品示例：SPF 50 不是 50 倍时间 / 水并没有在 2.45 GHz 共振 / MiniLED 其实还是 LCD / 它并不是"从里面往外熟"。

- 缺口必须真实存在（有权威来源支持正确解释），不为了戏剧性虚构矛盾。
- 缺口决定钩子页、误解转折页和收束页三个关键页的内容。
- 用户只给了主题时，先提出 1–3 个候选认知缺口让用户确认，或按 `ppt-copywriting-prompt.md` 第四节完成内部分析后再动笔。

### 第 2 步：先收集事实与数据，再设计页面

**先建数据底稿，再写文案。** 对每个候选论断做三件事：

1. **溯源**：优先政府机构、国际组织（WHO / IEA / FDA / NOAA）、同行评审文献（NEJM）、标准组织（IEEE / VESA / ISO）、第一方技术资料（DENSO WAVE）。来源不确定的标记「待核实」，不得写成事实。
2. **核口径**：每个数字确认它是什么、时间、统计对象和统计口径。来源有差异时写明差异（成品惯例：「USDA HOME-COOKING ESTIMATE · 实际深度随水分、盐分、温度和组成变化」）。
3. **翻译**：把每个抽象数字翻译成普通人可感知的量（见第六节）。翻译不出人话的数字，说明观众不需要它，删掉。

### 第 3 步：画叙事弧（deck 级结构）

按页数套用以下骨架，先输出分幕表再写单页：

```
钩子页（日常反差）→ 定调页（重新定义问题）→ 幕 I…IV（机制展开）
→ 转折页（纠正误解 / 代价与边界）→ 收束页（回收开头的问题）
```

幕结构的语义顺序固定为：

```
ACT I   · 这是什么（What）
ACT II  · 机制怎么运作（How）
ACT III · 反例与误解（Myth）
ACT IV  · 现实中的工程折衷（Trade-off）
ACT V   · 收束成一句话（Answer）
```

规则：

- 10 页以上必须分幕；幕标题格式 `ACT II · INSIDE THE FOOD`（英文大写 + 极短中文），写在页面顶部当路标。
- **误解转折页至少 1–2 页，且必须放在机制讲完之后**（先给足理解，再纠偏）。这是本项目最有辨识度的一步，不可省略。
- 幕节奏与主题 light/dark/hero 节奏表（AGENTS.md 第五节）对齐输出。
- 误解要拆解的是"流行解释"，不是稻草人：先复述那个好记但不准确的说法，再给出准确版本（成品原话：「纠正一个好记但不准确的解释」）。

### 第 4 步：逐页起草，先标题后正文

每页按固定顺序写：**标题（判断句）→ lead → 证据（数字卡/对比/pipeline）→ callout → source**。

- 写不出判断句标题，说明这页还没有观点：先重写内容，再排版。
- 一页只讲一个观点。标题是判断（"两套时钟并不同步"），不是话题（"关于电网的时间问题"）。
- 每页必须能回答：删除这页，故事损失了什么？
- 每页的关键数据 ≤3 个：多了说明这页在罗列而不是论证，拆页。

### 第 5 步：套句式库（见第五节），过质感线（见第七节）

从句式库中挑选句式填充，**避免连续两页使用同一句式**；每一句按第七节质感规则修剪。

### 第 6 步：跑自检门槛（见第十节）

全部通过才算完成；未通过回到对应步骤修改，不得带病交付。

## 三、页面文案 schema（六层信息，逐字段写）

每个正文页必须包含以下字段，缺一不可（视觉层的取舍由制作 agent 决定，文案层必须齐备）。**注意：这是目标模板，不是对历史成品的全貌描述**——历史产品并未全部齐备（例如冷链 deck 全篇无 source 行、多数 deck 的 callout 只在少量页面出现）。写新文案以本 schema 为准，越齐备越接近被认可的本项目风格；不要因为"成品里某字段缺了"就认为可以省。

| 字段 | 语言 | 长度约束 | 写什么 | 示例 |
|---|---|---|---|---|
| chrome | 英文大写 | ≤4 个实词 | 全 deck 统一的栏目名/页码 | `Page 05 · Balance` |
| kicker | 英文大写 + 短中文 | 同上 | 本页钩子，**必须与 chrome 内容不同** | `Quiet Zone · 安静区` |
| title | 中文 | 每行 ≤8 字，≤2 行 | 本页唯一的观点（判断句） | `液晶其实是一扇"光阀门"` |
| lead | 中文 | 单句 30–60 字 | 标题的展开：定义、设问、点破或边界 | 见下文 lead 四式 |
| 主体 | 数字 + 中文短说明 | 说明 ≤14 字 | 数字卡 / 对比卡 / pipeline 步骤 | `8.29M —— 每一帧的像素位置` |
| callout | 中文 | 一行 | 本页"带走的话"，套用金句句式 | `转盘做的是时间平均` |
| source | 机构名 + 年份 | 一行 | `机构 · 文献/主题 · 年份` | `SELECT · 17,604 participants · NEJM · 2023` |

字段纪律：

- **chrome ≠ kicker**。chrome 是栏目（`TIME · REFRESH RATE`），kicker 是本页钩子（`Refresh Rate · 刷新率`）。两者写重是历史 bug 清单里的明确错误。
- 四层信息（标题/lead/主体/callout）必须是同一件事的四个深度：标题给判断，lead 给展开，主体给证据，callout 给记忆点。
- 同组说明文字语气和密度必须一致，不人为制造主次差。
- 数字卡说明写成**最短名词短语**（`每一帧的像素位置`），禁止长定语从句——说明超过 14 字、或需要从句才能讲清，说明数字选错了，换一个更聚焦的数字（对应 AGENTS.md 13.14 复盘）。
- 标题用 `<br>` 手动断行：只切在**语义断点**，切出的每一行都要独立成立、可独立朗读，行末不留单字或标点（对应 AGENTS.md 13.11 / 13.13 复盘）。

### 三种页面主体的填空模板

**数字卡页**（3 张卡）：`两个事实 + 一个含义`，或 `三个梯度`。

```
卡1  [大数字]  [≤14字说明]
卡2  [大数字]  [≤14字说明]
卡3  [含义/对比收尾]  [≤14字说明]
```
成品示例：SPF 30 → 97% / SPF 50 → 98% / SPF 100 → 99%，callout「数字线性增加，过滤比例不是」。

**对比页（A vs B）**：两组各 `标签 + 一句机制描述`，底部用一句 `A ≠ B` 或对仗收尾。

```
A [名称]  [它在做什么，一句话]
B [名称]  [它在做什么，一句话]
callout: 「Build Fast ≠ Connect Fast」式对仗
```

**Pipeline 页**（4–6 步）：每步 `编号 + ≤10 字动宾短语`，步骤连起来必须是一条完整因果链，可以独立成句朗读。

```
01 [动宾短语≤10字]   02 [...]   03 [...]
```
成品示例（微波炉能量链）：01 插座里的电能 → 02 生成 2.45 GHz 波 → 03 交变电场进入食物 → 04 介电损耗耗散能量 → 05 材料自身变热。

## 四、三个关键页的固定写法

- **钩子页**：标题 = 日常可验证的反差（取观众当天就能验证的现象）；lead 直接点破"这件事和你想的不一样"。成品样本：「饭热了，盘子呢？」「它只需要 20 米」。
- **误解转折页**：标题 = 对流行说法的直接否定；lead 必须先复述那个好记但不准确的解释，再给准确版本。成品样本：「水并没有在 2.45 GHz 共振」。
- **收束页**：标题 = 新定义；lead = 把全 deck 各要素串成一句话；底部附要素链（`SPF × Broad Spectrum × Amount × Reapplication`）。收束不是总结列表。成品样本：「一张写给机器看的纸」「SPF 是数字，不是护盾」。

## 五、句式库（填空模板，附成品实例）

### 5.1 标题六式（每页从以下挑一种，相邻页不重句式）

1. **纠偏式**（主力，约占 9%）
   模板：`X 其实是 Y` / `X 不是 Y`
   实例：「SPF 50 不是 50 倍时间」「MiniLED 其实还是 LCD」「HDR 不是"把亮度拉满"」
2. **反差悬念式**
   模板：把两个矛盾事实并置，不加解释；问号仅在钩子页可用
   实例：「饭热了，盘子呢？」「发动机消失了，人声却还在」「黑色，也可以是一种"不发光"」
3. **数字具象式**
   模板：把抽象参数翻译成可想象的量，解释全部下放到卡片
   实例：「4K，其实是 829 万个位置」「每秒变化 24.5 亿次」「−14.9%」「它只需要 20 米」
4. **揭秘式**
   模板：`其实 / 还有 / 所以 / 才`
   实例：「一个像素里，还有三个小像素」「外面那圈白色也属于二维码」「所以盘子必须转起来」
5. **澄清边界式**
   模板：`A ≠ B` / `A 不代表 B`，专治概念混淆
   实例：「1ms 和 240Hz 根本不是一回事」「扫得出来，不代表它安全」「发得出，不等于接得住」
6. **收束定义式**（仅最后一页）
   模板：用一个新定义替换旧认知
   实例：「一张写给机器看的纸」「SPF 是数字，不是护盾」「微波炉真正加热的，是"材料性质"」

### 5.2 lead 四式（单句 30–60 字）

1. **重新定义**：「你看到的照片、游戏和电影，只是数百万个位置在正确时间控制正确数量的光。」
2. **设问推进**：「如果我们已经知道过去几十年大气是如何变化的，是否还需要每次重新求解全部方程？」
3. **点破误解**：「防晒霜上最大的那个数字，恰恰也是最容易被误解的数字。」
4. **给出边界**：「2.45 GHz 不是水分子的神奇频率；它只是一个水仍能有效吸收、又能进入食物一定深度的实用频率。」

禁止写"本页将介绍……"式导语；lead 直接给出本页的结论或张力。

### 5.3 callout 五式（每页一行）

- **不是 A，而是 B**：「转盘做的是时间平均」
- **A ≠ B**：「TRUST ≠ READABILITY」「Error Correction ≠ Decoration License」
- **同一 X，不同 Y**：「同一束微波，遇到不同材料，会走不同的热量路径」
- **对仗短句链**：「位置、光、时间和同步」「定位、方向、数据、冗余、恢复」（注意用顿号，不用间隔号）
- **日常化点题**：「很多"扫不出来"不是二维码坏了，而是白边被省掉了」

## 六、科普性要求：让零背景的人听懂

本项目所有 deck 都是科普分享（15–30 分钟场景），科普性不是风格偏好，是验收标准。

### 6.1 从生活切入，不从定义切入

- 每份 deck 的第一个内容页必须是观众**当天就能验证**的现象：饭热了盘子不热、扫码缺一块还能用、发动机声消失人声还在。
- 禁止用定义页开场（"X 是指……"）。定义在机制页里顺便给出。

### 6.2 术语纪律

- 术语首次出现必须"中文名 + 英文锚点 + 一句人话解释"三件套：`Quiet Zone · 安静区 · 让扫描器分辨哪里结束`。
- 术语之后只用中文名；同义词不混用（选定"介电损耗"就不再随机切换成"介质耗散"）。
- 一页最多引入 1 个新术语。需要 2 个以上就拆页。

### 6.3 抽象概念必须落地

- 每个抽象机制配一个日常类比或可感知的量：液晶是"一扇门"、刷新率是"下一张画面什么时候到来"、纠错是"提前把恢复所需的数学关系一起保存进去"。
- 类比只能帮助理解，不能替代机制说明；类比不准确的情形（如"水共振"）正是误解转折页要拆的对象。

### 6.4 语气

- 对观众用"你"，对论断保持克制；讲原理像博物馆展签，不下命令、不卖弄。
- 安全、健康类内容（如防晒、微波金属）必须落到可执行的行为建议上，但保留准确边界：「真正边界取决于形状、位置和设备说明」。

## 七、语言质感：优雅 · 简洁 · Apple 风

> Apple 风在这里只指语言秩序：信息密度高、句子短、修饰少、每句话都经得起读第二遍。不模仿品牌话术，不写广告腔。

### 7.1 短句节奏

- **一句一个意思，句号切开**。长从句一律拆成两短句。成品样本：「冰箱真正做的事，不是让食物停止变化，而是让变化变慢。冷链，是人类用工程手段对抗时间。」
- 定调句追求"一口气读完、一次就懂"，力求成金句。「低温，让世界第一次学会保存新鲜。」「人类发明钟表，不只是为了知道几点，而是为了让世界一起行动。」

### 7.2 重定义句：本项目的招牌修辞

「**不是 A，而是 B**」是全库出现频率最高的修辞动作，也是 Apple 发布会的标志性句式：

- 「钟表真正改变的，不是时间本身，而是人类协作的尺度。」
- 「时间从自然现象，逐渐变成一种纪律。」
- 「新鲜，是设计出来的。」（Freshness Is Engineered）

用法：先接住观众的旧理解，再给出新理解。每份 deck 至少在定调页和收束页各出现一次。

### 7.3 删到不能再删

- **砍空洞副词和形容词**：删掉"非常""极其""巨大的""深刻的"——如果删掉后句子仍然成立，就必须删。力量放进名词和动词。
- **主动语态**："微波加热了食物"，不写"食物被微波所加热"。
- **具体名词优先**："牛奶、海鲜、水果和疫苗"，不写"各类物品"；"39,123 颗"，不写"大量"。
- **数字本身就是修辞**：能用 `144+ 种地方时间` 就不要写"混乱不堪"。

### 7.4 收尾的节奏感

- 金句收尾可以采用名词短语链或英文短 aphorism（≤4 词），做出"发布会落幅"感。成品样本：「Freshness, designed, delivered, shared.」「Smarter Cold. Less Waste.」「位置、光、时间和同步」「安静的奇迹」。
- 全 deck 最多 1–2 处这种落幅句；普通页面保持平实，金句泛滥等于没有金句。

### 7.5 修辞的分寸

- 允许一个贯穿全 deck 的核心隐喻（光纤 = 玻璃神经、画面 = 坐标表、二维码 = 写给机器的纸），且该隐喻必须服务于理解机制。
- 禁止装饰性隐喻（"时代的齿轮""文明的脉搏"式空转修辞，见 `ppt-copywriting-prompt.md` 第八节词表）。隐喻里必须能装进事实，装不进的删掉。

## 八、客观事实与数据引用纪律（硬门槛）

### 8.1 事实纪律

1. **严禁编造**数据、年份、人物、案例、引用或机构；严禁把推测写成事实、把相关性写成因果、为戏剧性夸大数字。
2. 来源无法确认 → 标记「待核实」并告知用户；来源有差异 → 写明口径差异，不擅自选边。
3. 论断分层：有数据支撑的写成断言；只有定性证据的写成「通常 / 约 / 一般」；两者都没有的不写。
4. 对立观点和代价必须保留位置（GLP-1 deck 的"停药之后，身体会反击""有效，不代表没有代价"）——单边叙事不符合本项目风格。

### 8.2 数据引用格式（五条纪律）

1. **大数字必须配一句人话说明**（≤14 字）：`2,500 GW —— Grid Connection Queue`；展示位数 ≤4 位，大数用 K/M/B 缩写（`1.6 B`、`526M Tonnes`）。
2. **抽象量必须翻译成可感知的量**：不说"波长短"，说 `12.2 cm —— 自由空间中的约略波长`。
3. **结论永远带条件**：「特定试验、特定人群和特定剂量下的结果」「特定 35 秒建模条件」。
4. **来源行固定格式**：`机构 · 文献/主题 · 年份`。正文关键数字页必须带 source 字段；没有来源的数字降级为定性描述，不得保留精确值。
5. **对比用第三卡收尾**：三张数字卡通常是"两个事实 + 一个含义"或"三个梯度"（SPF 30/50/100 → 97%/98%/99%）。

### 8.3 数据密度

- 每页关键数据 1–3 个：少到撑不起判断就补数据，多到说明不了单一观点就拆页。
- 数字只为论断服务：删掉这个数字论断不变，就删数字。
- 数字的数量和长度决定一页的信息密度：超过 3 个关键数据、或说明超 14 字，页面就从"论证"退化成"罗列"，应拆页或删减（对应 AGENTS.md 13.12 复盘）。

## 九、语言风格（Do / Don't）

> 本节是把第六～八节的规则压缩成的快速对照表，用于逐句自查；与上文重复是故意的，细则以对应小节为准。

### 必须做

- 口语但精确：允许"饭热了，盘子呢"，但每个论断落在具体数字和机构来源上。
- 该 hedge 的地方一定 hedge：用「约」「通常」「典型」「实际深度随水分、盐分、温度和组成变化」。不写"一定、永远、最"。
- 专有名词按 6.2 三件套处理；英文行全部大写、≤4 个实词、只做标签；从不写英文长句正文。
- 英文承载标签，中文承载意义：观众完全忽略英文也能读懂全篇。
- 每一句话过一遍第七节质感线：短句、主动、具体、零冗余修饰。

### 禁止做

- 营销词：作**描述性程度词**可（成品有"一秒被重新定义"、chips deck"一场昂贵到极致的工程"），但禁止作**空泛口号**（"改变世界""颠覆传统""重新定义行业"这类没有信息量的套话）——差异在是否给出具体对象和因果。
- 话题式标题：「发展历史」「市场规模」「工作原理」「未来趋势」。
- 绝对化论断、无来源精确数字、虚构矛盾、定义页开场。
- 空洞修饰词和装饰性隐喻（"非常""巨大""时代的齿轮""文明的脉搏"）。
- 同组文字人为设置不一致的语气密度或主次透明度。
- 标题超过 2 行、lead 超过 70 字不拆分。

## 十、交付前自检门槛（全部通过才可交付）

**定位级**

- [ ] 认知缺口明确且真实（正确解释有权威来源），钩子页 / 误解转折页 / 收束页三页已落实
- [ ] 第一内容页从日常生活切入，不是定义页开场
- [ ] 全篇零背景可懂：每个术语有三件套解释，一页 ≤1 个新术语

**Deck 级**

- [ ] 10 页以上已分幕，幕结构语义顺序正确
- [ ] 误解转折页 ≥1 页，且位于机制页之后
- [ ] 收束页用新定义回收了开头的问题，不是总结列表
- [ ] 相邻页标题句式不重复；疑问句标题全 deck ≤2 处
- [ ] 输出了与 light/dark/hero 节奏表对齐的分幕表

**页级（逐页过）**

- [ ] 六层字段齐备：chrome / kicker / title / lead / 主体 / callout / source
- [ ] chrome ≠ kicker
- [ ] 标题每行 ≤8 字、≤2 行，是判断句不是话题
- [ ] lead 单句 30–60 字，无"本页将介绍"式导语
- [ ] 一页一观点、关键数据 1–3 个；pipeline 步骤连读是完整因果链
- [ ] 数字卡说明 ≤14 字；数字有来源、有边界、有人话说明
- [ ] 数字卡说明是最短名词短语，无长定语从句
- [ ] 标题 ≤2 行、每行 ≤8 字（`<br>` 手动断行）；断点处两行均可独立朗读、行末无单字/标点

**质感级**

- [ ] 定调页和收束页各有一个"不是 A，而是 B"式重定义句
- [ ] 逐句检查：一句一个意思，无长从句堆叠
- [ ] 空洞副词/形容词已删净；具体名词和数字优先
- [ ] 落幅金句全 deck ≤2 处；核心隐喻贯穿且服务于理解
- [ ] 朗读测试：标题和 callout 读出来有发布会字幕感，一次就懂

**事实级**

- [ ] 无编造数据/年份/案例/机构；「待核实」项已明确标出
- [ ] 关键数字页全部带 `机构 · 文献 · 年份` 格式来源行
- [ ] 结论带边界条件；对立观点与代价未被删掉
- [ ] 无**空泛**营销口号（"改变世界""颠覆传统"类）；营销词如使用须为**描述性程度词**且给出具体对象（见 §九），无绝对化论断、无 AI 味表达（对照 `ppt-copywriting-prompt.md` 第八节词表）

## 十一、输出格式

按页输出文案清单，每页一个块，供制作 agent 直接消费：

```
## P{n} · {布局类型：数字卡页 / 对比页 / pipeline页 / 引用页 / hero页}
chrome:  {英文大写栏目 · 页码}
kicker:  {英文大写 + 短中文}
title:   {中文标题，含 <br> 断行}
lead:    {单句}
主体:
  - {卡1：数字/标签 —— ≤14字说明}
  - {卡2：...}
  - {卡3：...}
callout: {一行金句}
source:  {机构 · 文献 · 年份}
备注:    {动效叙事类型（hero/quote/pipeline/directional），供 data-animate 选择参考}
```

Deck 级先交付三样东西，确认后再逐页产出：

1. 认知缺口一句话（含"流行解释 vs 准确解释"对照）；
2. 数据底稿摘要（关键数字 + 来源 + 口径）；
3. 分幕表（页码 · 幕 · light/dark/hero · 标题句式 · 布局类型）。

## 一句话版本

> 给普通人的数据科普，写得像 Apple 发布会字幕一样简洁克制：先找到"大家以为 X 其实 Y"的缺口，用生活现象开场、用权威数据立论；每页一个判断句标题、一句 lead、带人话说明和来源的数字、一行金句；句子短而具体，删净空洞修饰；误解专门开页纠，英文只当标签，收束时用一个新定义换掉观众脑子里那个旧的。
